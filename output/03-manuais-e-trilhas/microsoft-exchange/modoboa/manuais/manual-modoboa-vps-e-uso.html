Módulo 0: Nivelamento Conceitual (O que você precisa saber antes de começar)

Zero Programação

Você não precisa ser engenheiro de software para entender como o sistema funciona. Abaixo explicamos os 5 conceitos-chave usando analogias do cotidiano:

💡 Modoboa
Analogia: Departamento Correios Inteligente

Gerenciador central de emails. Recebe (Postfix), guarda (Dovecot), controla (Django).

💡 Postfix
Analogia: Entregador Cartas

Carteiro que sai pela porta com cartas endereçadas (porta 25 SMTP).

💡 Dovecot
Analogia: Gerente Gavetas Correspondência

Coloca carta certa com nome funcionário (portas 143 IMAP ou 110 POP3).

💡 Django/Python
Analogia: Painel Controle Centralizado

Painel web onde admin clica criar usuários, domínios.

💡 PostgreSQL
Analogia: Arquivo Central Documentos

Banco dados: usuários, domínios, permissões, filtros, histórico.

Socorro! O que fazer se algo não funcionar (Troubleshooting para Leigos)

⚠️ Sintoma: Emails chegam em spam
Causa Provável: SPF, DKIM ou DMARC não configurados
Solução Prática: Verificar registros SPF/DKIM no painel. Adicionar no DNS do registrador.
⚠️ Sintoma: Port 25 blocked - emails não saem
Causa Provável: ISP bloqueou porta 25 (comum em residencial)
Solução Prática: Configure relayhost para smarthost confiável via porta 587 em /etc/postfix/main.cf
⚠️ Sintoma: IMAP não conecta com erro
Causa Provável: Dovecot não está rodando ou permissões /var/vmail erradas
Solução Prática: sudo systemctl restart dovecot && sudo chown -R vmail:vmail /var/vmail
⚠️ Sintoma: Painel web fica lento ou travado
Causa Provável: PostgreSQL sob pressão ou muitos usuários simultâneos
Solução Prática: sudo systemctl restart modoboa && monitorar pool connections
⚠️ Sintoma: ClamAV/SpamAssassin consumindo 100% CPU
Causa Provável: Muitos emails grandes sendo processados simultaneamente
Solução Prática: Reduza MaxThreads em /etc/clamav/clamd.conf ou desative ClamAV

Desinstalação Cirúrgica & Limpeza da VPS (Sem Comprometer Outros Projetos)

Isolamento Total

🛡️ Princípio de Isolamento da VPS (Zero Efeito Colateral)

Remove exclusivamente instância Modoboa (Django, dados email, bancos SQL). Preserva Postfix, Dovecot, certificados SSL e SO.

Passo 1 Parada de Serviços Modoboa

Para Django (Gunicorn) e Celery sem afetar Postfix/Dovecot/Nginx

sudo systemctl stop modoboa
sudo systemctl disable modoboa
sudo systemctl stop modoboa-celery
sudo systemctl disable modoboa-celery
⚠️ Alerta de Segurança: NÃO execute 'systemctl stop postfix' ou 'systemctl stop dovecot'
✅ Como Validar: sudo systemctl is-active modoboa # Retorna 'inactive'
Passo 2 Remoção do Banco PostgreSQL

Deleta schema Modoboa, preservando outros bancos

sudo -u postgres psql -c "DROP DATABASE IF EXISTS modoboa;"
sudo -u postgres psql -c "DROP USER IF EXISTS modoboa;"
⚠️ Alerta de Segurança: JAMAIS execute 'DROP DATABASE postgres;'
✅ Como Validar: sudo -u postgres psql -l | grep modoboa # Não deve aparecer
Passo 3 Remoção de Diretórios

Remove /var/vmail/modoboa (dados) e /opt/modoboa (código)

sudo rm -rf /var/vmail/modoboa
sudo rm -rf /opt/modoboa
sudo rm -f /etc/systemd/system/modoboa.service
sudo rm -f /etc/systemd/system/modoboa-celery.service
⚠️ Alerta de Segurança: Não execute 'rm -rf /' nem 'rm -rf /var/'
✅ Como Validar: ls -ld /var/vmail/modoboa 2>&1 | grep 'cannot access'
Passo 4 Limpeza Nginx

Remove virtual host Modoboa do Nginx

sudo rm -f /etc/nginx/sites-enabled/modoboa
sudo rm -f /etc/nginx/sites-available/modoboa
sudo systemctl reload nginx
sudo systemctl daemon-reload
⚠️ Alerta de Segurança: Mantenha outros sites em /etc/nginx/sites-available/
✅ Como Validar: sudo nginx -t # Retorna 'configuration OK'

🩺 Checklist de Saúde da VPS (Confirmar que outros projetos continuam online)

  • ps aux | grep -E '(gunicorn|celery|modoboa)' # Nenhum processo deve aparecer
  • sudo -u postgres psql -l # Banco 'modoboa' não deve estar na lista
  • sudo systemctl status postfix # Deve estar 'active'
  • sudo systemctl status dovecot # Deve estar 'active'
  • sudo systemctl status nginx # Deve estar 'active'
  • free -h # RAM devolvida ao sistema
