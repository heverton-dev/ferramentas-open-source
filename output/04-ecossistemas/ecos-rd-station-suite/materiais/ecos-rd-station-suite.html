🛡️ Segurança e Topologia de Rede: A infraestrutura opera sobre uma rede bridge isolada do Docker (`ecosystem_net`). Apenas o reverse proxy Traefik expõe as portas públicas 80 (HTTP com redirect) e 443 (HTTPS TLS automático via ACME/Let's Encrypt). Todas as ferramentas (Mautic, Twenty, Chatwoot, Evolution, n8n, Keycloak e PostgreSQL) comunicam-se exclusivamente pela rede interna através de seus nomes DNS de serviço (ex: `http://chatwoot:3000`, `postgres:5432`), eliminando vetores de ataque externos e exposição de portas desnecessárias.

Composição dos Serviços de Infraestrutura

Traefik Proxy v3

traefik:v3.0

Papel na Stack: Ingress Controller & Reverse Proxy com TLS automático

Por que foi escolhido: Descobre contêineres dinamicamente via labels do Docker sem necessidade de recarregar Nginx manualmente. Emite certificados SSL Let's Encrypt para múltiplos subdomínios corporativos.

🔌 80:80 (HTTP) e 443:443 (HTTPS) 💾 Volume `/letsencrypt/acme.json` para certificados

Keycloak SSO

quay.io/keycloak/keycloak:latest

Papel na Stack: Provedor Central de Identidade (IdP) & Single Sign-On (OIDC/SAML)

Por que foi escolhido: Elimina silos de senhas: os colaboradores usam a mesma credencial corporativa para acessar o CRM (Twenty), o Atendimento (Chatwoot), as Landing Pages (Directus) e a Automação (Mautic).

🔌 Apenas rede interna (exposto via Traefik em `sso.empresa.com.br`) 💾 PostgreSQL corporativo compartilhado

n8n Automation

n8nio/n8n:latest

Papel na Stack: Barramento de Eventos & Orquestração Assíncrona de Dados

Por que foi escolhido: Funciona como a 'cola' do ecossistema. Substitui o Zapier/Make com interface visual no-code, processando webhooks e roteando leads do Typebot para o Mautic, CRM e WhatsApp sem código customizado.

🔌 Apenas rede interna (exposto via Traefik em `n8n.empresa.com.br`) 💾 Volume `/data/.n8n` ou PostgreSQL

Cluster PostgreSQL

postgres:16-alpine

Papel na Stack: Banco de Dados Relacional Consolidado

Por que foi escolhido: Instância única otimizada com bancos lógicos dedicados (`db_mautic`, `db_twenty`, `db_chatwoot`, `db_keycloak`, `db_n8n`), reduzindo drasticamente o consumo de memória RAM na VPS.

🔌 Nenhuma porta pública (porta 5432 restrita à rede `ecosystem_net`) 💾 Volume de dados `/var/lib/postgresql/data` com política diária de pg_dump

Redis Cache & Queue

redis:7-alpine

Papel na Stack: Fila de Mensageria em Memória & Sessões WebSockets

Por que foi escolhido: Gerencia as filas de alta velocidade do Chatwoot (atendimento em tempo real), Evolution API (sessões Baileys do WhatsApp) e n8n (execuções em background).

🔌 Nenhuma porta pública (porta 6379 restrita à rede `ecosystem_net`) 💾 Volume persistente `/data` (AOF habilitado)

Passos de Subida do Ambiente

01 Provisionamento do Host

Contrate uma VPS de 8 vCPU / 16 GB RAM com Ubuntu 22.04 LTS e instale Docker Engine e Docker Compose.

02 Configuração de DNS Wildcard

Crie uma entrada DNS tipo A apontando `*.suaempresa.com.br` para o IP público da VPS.

03 Subida do Cluster Integrado

Execute `docker compose up -d` na pasta do ecossistema e acesse os painéis com certificados SSL automáticos.

Seção 06 · Guia de Modularidade & Hot-Swap

Adição, Substituição & Remoção de Módulos

Como personalizar o ecossistema e trocar ferramentas sem quebrar o cluster nem interromper a operação.

🧩 Princípio de Acoplamento Fraco: A arquitetura foi projetada sob o princípio de Acoplamento Fraco (Loose Coupling). Nenhuma ferramenta conversa com outra de forma proprietária rígida. Todas as trocas de informação ocorrem através de Webhooks padronizados no barramento n8n e autenticação federada via OpenID Connect no Keycloak. Isso significa que qualquer componente da stack pode ser inserido, substituído ou removido como um bloco de Lego, sem afetar o funcionamento dos outros serviços.

1. Protocolo de Inserção de Novas Ferramentas

1. Definição do Serviço no Docker Compose

Adicione o novo serviço ao arquivo `docker-compose.override.yml` (evitando alterar o arquivo principal). Vincule-o obrigatoriamente à rede `ecosystem_net` e defina as labels do Traefik para roteamento sob o subdomínio desejado (ex: `forms.suaempresa.com.br`).

2. Provisionamento do Banco de Dados

Caso a ferramenta necessite de persistência relacional, crie uma base de dados dedicada no cluster PostgreSQL existente (`CREATE DATABASE db_nova_ferramenta;`) em vez de subir outro contêiner de banco.

3. Conexão ao Barramento de Eventos (n8n)

Configure o webhook de saída da nova ferramenta apontando para um endpoint de gatilho no n8n (`http://n8n:5678/webhook/novo-evento`), integrando-a instantaneamente ao CRM e WhatsApp.

4. Federação de Identidade no Keycloak (Opcional)

Se a ferramenta suportar OIDC/OAuth2, crie um novo Client no realm corporativo do Keycloak para que a equipe utilize a mesma credencial de login.

2. Protocolo de Hot-Swap (Substituição de Ferramenta sem Downtime)

1. Subir o Novo Serviço em Paralelo: Inicie o novo contêiner em um subdomínio temporário (ex: `novo-mkt.empresa.com.br`) na mesma rede `ecosystem_net`; 2. Replicar os Fluxos no n8n: Crie uma versão paralela do workflow no n8n apontando para a nova ferramenta; 3. Migração de Dados: Exporte os contatos/histórico do serviço antigo e importe no novo; 4. Virada de Rota no Traefik: Altere a label do Traefik no `docker-compose.yml` para que o subdomínio principal (`mkt.empresa.com.br`) passe a apontar para o novo contêiner; 5. Descomissionamento Seguro: Desligue o contêiner antigo com `docker compose stop ` e preserve o volume de backup.

3. Protocolo de Remoção Segura de Serviços

1. Desative os nós correspondentes no n8n para evitar erros de webhooks não respondidos; 2. Remova as labels do Traefik para liberar a rota pública; 3. Execute `docker compose stop ` e `docker compose rm `; 4. Mantenha os volumes de dados arquivados em storage secundário para histórico.

4. Estudo de Caso Prático: Substituição do Mautic por outra ferramenta de automação (ex: Activepieces ou Novu)

1. Isolamento Operacional: O Twenty CRM e o Chatwoot não conversam diretamente com o Mautic; eles conversam com o n8n. Logo, o CRM e o WhatsApp continuam operando 100% normalmente.

2. Início do Novo Contêiner: Sobe-se o novo contêiner no `docker-compose.override.yml` com a label `traefik.http.routers.automacao.rule=Host('automacao.empresa.com.br')`.

3. Chaveamento no n8n: No n8n, substitui-se o nó 'Mautic: Create Lead' pelo nó 'Activepieces: Trigger Flow'. Nenhuma linha de código ou configuração nos outros módulos precisa ser alterada.

4. Veredito Final: A migração ocorre com ZERO impacto para vendedores no CRM e ZERO impacto para operadores no Chatwoot.
