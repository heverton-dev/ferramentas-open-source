🔴 Severidade CRÍTICA (3 achados)

CRÍTICA
1. Credenciais Hardcoded em Arquivo .env Versionado
Arquivo: .env | Linhas: 3, 8, 13, 18
Categoria: CHAVES EXPOSTAS
Descrição:

Arquivo .env com GitHub Token, Portainer Password, VPS Password e Mautic Password expostos no repositório Git.

Explorabilidade:

Qualquer pessoa com acesso ao Git pode acessar credenciais reais de produção (GitHub PAT, senhas VPS, Portainer, Mautic).

Impacto:

CRÍTICO - Comprometimento de múltiplos sistemas: GitHub (criar forks, deletar branches), Portainer (controle total de containers), VPS (acesso root), Mautic (acesso ao sistema de email).

CRÍTICA
2. .env Não Está Realmente Ignorado no Git (Histórico Compromisso)
Arquivo: .gitignore linha 19 + histórico Git
Categoria: CHAVES EXPOSTAS
Descrição:

.gitignore marca .env para ser ignorado, mas o arquivo já foi commitado anteriormente e permanece no histórico Git.

Explorabilidade:

git log -p --all | grep PASSWORD retorna 25+ segredos commitados:

  • OnlyOfficeSecretKey2026_SecureToken!
  • SenhaSegura123456789AleatoriaMuitoForte
  • WorkspaceDBSecret_2026!
  • SenhaSegura123!MauticVPS
  • senhadoemail
Impacto:

CRÍTICO - Histórico permanente que não pode ser apagado sem reescrita de Git (git filter-branch).

CRÍTICA
3. Segredos Padrão Documentados em HTMLs Públicos (Fluxo 5)
Arquivo: output/05-auditorias-vps/*/guias/guia-instalacao-cirurgica-*.html
Categoria: CHAVES EXPOSTAS
Descrição:

HTMLs gerados contêm segredos padrão de exemplo (OnlyOfficeSecretKey2026_SecureToken!, SenhaSegura123456789AleatoriaMuitoForte, WorkspaceDBSecret_2026!) que podem ser reusados ou servir como defaults.

Explorabilidade:

Administradores podem copiar valores de exemplo e deixar em produção sem regenerar. Baixa entropia = vulnerável a força bruta.

Impacto:

MÉDIO-ALTO - Falha operacional de segurança em escala (cada documentação gera risco).

🟠 Severidade ALTA (2 achados)

ALTA
4. Ausência de Mecanismo de Isolamento por Tenant/Organização
Arquivo: core/, db/, gates/ (estrutura geral)
Categoria: BANCO SEM TRANCA
Descrição:

SQLite não implementa isolamento de dados por tenant. Projeto é monousuário/single-org, mas falta RLS ou filtro de acesso.

Explorabilidade:

Se convertido para API multi-tenant sem adição de filtros row-level, todos os usuários poderiam listar/acessar dados de todas as organizações.

Condição:

Risco materializado APENAS se projeto evoluir para multi-tenant sem implementar isolamento.

ALTA
5. Mensagem de Commit Sem Validação de Input
Arquivo: scripts/git_sync.py | Linha: 71
Categoria: INPUTS SEM TRATAMENTO
Descrição:

sys.argv[1] é passado diretamente como mensagem de commit sem sanitização ou validação.

Explorabilidade:

Embora subprocess.run use lista (seguro contra shell injection), caracteres especiais podem quebrar a flag -m ou injetar flags de commit como --no-verify ou --amend.

🟡 Severidade MÉDIA (2 achados)

MÉDIA
6. innerHTML com Interpolação de Template String (XSS Risk)
Arquivo: scripts/gerar-index-organizacao.py:196, scripts/aplicar_padrao_diamante_49.py:53
Categoria: INPUTS SEM TRATAMENTO
Descrição:

Uso de .innerHTML = `...${variable}...` em JavaScript gerado. Embora os valores sejam números internos (seguro no contexto atual), padrão é anti-pattern.

Explorabilidade:

Se refatorar para aceitar dados de input do usuário sem sanitizar, risco de XSS.

MÉDIA
7. Falta de Validação de Startup para Variáveis Críticas
Arquivo: .env linhas 1, 6, 10, 15
Categoria: CHAVES EXPOSTAS
Descrição:

Projeto carrega .env mas não valida se valores críticos foram sobrescritos ou permanecem como defaults.

Explorabilidade:

Se script for rodado sem .env ou com valores defaults, sistema opera com credenciais de exemplo.

🔵 Severidade BAIXA (1 achado)

INFORMATIVA
8. Padrão de Queries SQL Seguro (Ponto Forte)
Arquivo: scripts/estado_esteira.py (linhas 26-100 e queries SQL)
Categoria: BANCO SEM TRANCA
Verificação:

Queries SQLite usam parametrized statements (?) corretamente. RECOMENDAÇÃO: manter assim em futuras adições.

Recomendações Priorizadas

P1 - CRÍTICO (Executar imediatamente)

  • Regenerar GitHub Token: Settings > Developer settings > Personal access tokens > Delete + regenerate
  • Remover .env do Git: Use git filter-branch ou BFG Repo-Cleaner para remover de todo histórico
  • Regenerar PORTAINER_PASSWORD e VPS_PASSWORD
  • Implementar .env.local: Criar .env.example com placeholders (${VAR}), adicionar .env e .env.local ao .gitignore ANTES de recomitar
  • Implementar validação de startup: Script deve falhar rápido se credenciais são defaults públicos

P2 - ALTA (Próximas 48 horas)

  • Varrer histórico Git: Usar git-secrets ou truffleHog para identificar todos os segredos commitados
  • Adicionar pre-commit hook: Bloquear commits contendo patterns de secrets (password=, token=, secret=, etc)
  • Remover segredos de HTMLs: Substituir valores hardcoded por placeholders (${ONLYOFFICE_SECRET}, ${DB_PASSWORD})

P3 - MÉDIA (Semana 1)

  • Validar input em git_sync.py: Apenas alphanumerics, espaço, hífen, parenteses em mensagem de commit
  • Refatorar innerHTML: Usar textContent em vez de innerHTML para conteúdo dinâmico; se HTML necessário, usar DOMPurify
  • Documentar padrões seguros: Adicionar seção no CLAUDE.md proibindo innerHTML com interpolação e secrets hardcoded

P4 - PREPARAÇÃO (Se expandir para multi-tenant)

  • Implementar isolamento de tenant: RLS em SQLite (via função user_id), ou adicionar filtro manual em todas as queries
  • Auditoria de acesso: Criar tabela de logs de acesso a recursos

--- ISSUE 1 ---

[Segurança] Credenciais Hardcoded em .env Versionado + Histórico Git

Severidade: CRÍTICA
Labels: security, critical

PROBLEMA:
- .env contém GitHub Token, Portainer Password, VPS Password, Mautic Password e está commitado no Git
- Histórico Git contém 25+ segredos adicionais (JWT secrets, DB_PASSWORD, etc)

EVIDÊNCIA:
- .env linhas 3, 8, 13, 18
- git log -p --all | grep PASSWORD

IMPACTO:
- Qualquer pessoa com acesso ao repositório pode acessar credenciais reais de produção
- GITHUB_TOKEN pode ser abusado para criar forks, deletar branches, acessar outros repos
- PORTAINER_PASSWORD permite controle total do painel Docker
- VPS_PASSWORD permite acesso root ao servidor

CORREÇÃO:
1. git filter-branch --tree-filter 'rm -f .env' HEAD (ou BFG Repo-Cleaner)
2. Regenerar GitHub Token (Settings > Developer settings > Personal access tokens)
3. Regenerar PORTAINER_PASSWORD e VPS_PASSWORD
4. Adicionar .env ao .gitignore ANTES de recomitar
5. Criar .env.example com placeholders

ACEITE:
- [ ] .env removido do histórico Git
- [ ] Credenciais regeneradas
- [ ] .env adicionado ao .gitignore
- [ ] .env.example documentado
